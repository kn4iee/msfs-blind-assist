# BlueBird 757 EHSI reader rules

Loaded when Claude reads matching code. Background: docs/b757.md. Full text: docs/invariants/b757-ehsi.md. The shared 757 rules (B757-30 and on) are in b757.md.

- [B757-36] `Bbs757EhsiReader` reads the flown legs, legs, pending modification and points all or nothing: a torn vector, a leg or label outside the module, a count over the cap or a non-finite or out-of-range position makes the reading `Corrupt`, no partial route; a discontinuity is its own leg with no row, never a leg across it. Full: docs/invariants/b757-ehsi.md#b757-36
- [B757-37] `Bbs757EhsiText` lists a map item only where the EHSI draws it: projected by `Bbs757EhsiGeometry.Project` from the nd's center and rotation and inside `OnScreen`'s clip (circle at 88.7 % of range, PLAN too, plus the screen's edges), never by distance against the range alone; constants from the layout. Full: docs/invariants/b757-ehsi.md#b757-37
- [B757-38] `HotkeyAction.ReadNDWaypoint` says `Bbs757EhsiDisplay.WaypointLine`: the active leg's name (a pending modification's leg 0, else the route's; the top line draws none), then the top line's distance and ETA as drawn ("no ETA" under 100 kt); interrupting, window open or closed, never muted by the Ctrl+M row. Full: docs/invariants/b757-ehsi.md#b757-38
- [B757-39] `Bbs757EhsiDisplay.SimInputs` takes `PLANE LATITUDE` and `PLANE LONGITUDE` because BlueBird's top-line draw reads them (an input, never compared with memory, [B757-30]); the map rows use the nd's own center. Never swap one for the other. Full: docs/invariants/b757-ehsi.md#b757-39
- [B757-40] `Bbs757EhsiReader`'s part walks are all or nothing ([B757-36]): `TryTcas`'s traffic, `TryMapOptions`' lists, `TryRunway`, `TryDeceleration`, `TryCapabilities`, `TryFix`, `TryFixEntries`; a torn read is `Corrupt`, no partial list, until that part has torn `TearLimit` readings in a row: then it alone reads "not read: unexpected values". Full: docs/invariants/b757-ehsi.md#b757-40
- [B757-41] A `Bbs757EhsiLayout` part missing, not derived, refused by `LayoutProblems` or torn `TearLimit` readings in a row costs only its rows (one "<part>: not read: <reason>" row from `Bbs757EhsiText`), never the reader; a part is null exactly when its `…Missing` reason is set (`CheckParts`); only `[LayoutFileOptional]` members may be absent. Full: docs/invariants/b757-ehsi.md#b757-41
- [B757-42] `Bbs757EhsiMapOptionsLoop` replays BlueBird's draw loop (one item per switched-on list a round, counted to the layout's limit, the round limit, the restart on a skipped NDB) and `Bbs757EhsiText` lists only its drawn items inside `OnScreen`; never a plain range filter over the lists: BlueBird stops at the count; later items are not drawn. Full: docs/invariants/b757-ehsi.md#b757-42
- [B757-43] Traffic, map options, TERR, wind, runways, deceleration points and guides are rows only: of plan 28's items `Bbs757EhsiText.Changes` speaks only the LOC and G/S flags and the TCAS words (not TFC, not TEST), once after the settle, never when they come or go only as the EFIS mode or the gate byte changed (`ApproachFlags`, `TcasMessages`). Full: docs/invariants/b757-ehsi.md#b757-43
- [B757-44] An L:var BlueBird's EHSI draw reads comes from its handle's cached value in memory (the layout's handle value offset), never SimConnect; `Bbs757EhsiDisplay.SimInputs` holds only what the draw takes from the simulator with no copy in memory (the position, the wind's two inputs, the gear), in the draw's own units. Full: docs/invariants/b757-ehsi.md#b757-44
- [B757-45] A leg of the layout's `CapabilityLegKind` (route legs and FIX fixes) takes its position by its capability set and `CapabilityChoices`, BlueBird's rule (`LegPositionOffsets`); never by the primary position alone: a TACAN-only station's reads 0, 0 (measured: TCM). Full: docs/invariants/b757-ehsi.md#b757-45
- [B757-46] The EHSI rows copy the draw's own condition, never a tidier one, even where BlueBird looks wrong: TCAS FAIL hides the left block's other words only with the gate byte set (`FailShown`); `TerrainNumber` compares the gear input with the layout's gear-down value as the draw does; `WindRow` shows dashes exactly when the show flag is clear. Full: docs/invariants/b757-ehsi.md#b757-46
- [B757-47] Magnetic against true: the course pointer, the FIX radial and the VOR course lines turn against `Bbs757EhsiReading.Number` (the screen's own heading number, magnetic or true); the bearing pointers, the wind, traffic and every map item against `Bbs757EhsiMap.Rotation` (true). Never swap them. Full: docs/invariants/b757-ehsi.md#b757-47
- [B757-48] The measured signs stand: a positive VOR or localizer deviation is right of the course (fly right), a positive glideslope value is above, traffic trend 1 is climbing, the traffic tag's sign is the relative altitude's (`Deflection`, `TrendWords`). Pinned by live captures; never flip one to "look right". Full: docs/invariants/b757-ehsi.md#b757-48
- [B757-49] `Bbs757EhsiReader.TryParts` reads a part's values only in the modes that draw them (the VOR and ILS picture in VOR and ILS, the bearing pointers but in PLAN, traffic in MAP, map items while the map is drawn); a value no row can show is never read: it could only add a way to turn `Corrupt`. Full: docs/invariants/b757-ehsi.md#b757-49
