# BlueBird 757-200 rules

Loaded when Claude reads matching code. Background: docs/b757.md. Full text of each rule: docs/invariants/b757.md.

- [B757-1] Never read or register the stock `BRAKE PARKING POSITION` on the 757: it read 0 with BlueBird's brake set (measured). The parking brake is `L:B757_FC_PARK_BRAKE`: the Control stand toggle and the status row `Bbs757Readouts.ParkingBrakeKey`. Full: docs/invariants/b757.md#b757-1
- [B757-2] The EFB's CHOCKS tile TOGGLES: never press it without first reading `L:BBS757_vis_chocks` and pressing only when it differs from the wanted one (`Bbs757EfbLayout.MayClickChocks`); an unread state presses nothing. Full: docs/invariants/b757.md#b757-2
- [B757-3] Never step the MCP speed one `K:AP_SPD_VAR_INC/DEC` per knot in one burst: BlueBird speeds a burst up (events 1-10 move 1 kt, 11-25 2 kt, then 5 kt; measured). Plan it with `Bbs757Mcp.SpeedBursts` and correct in bursts of at most `Bbs757Mcp.LinearBurstMax`, each `Bbs757Mcp.SpeedBurstGapMs` apart. Full: docs/invariants/b757.md#b757-3
- [B757-4] Run the EFB load (`Bbs757EfbLayout.LoadThroughEfb`) only when `Bbs757Loadsheet.UnitsRefusal` returns null and no units question may be open (`Bbs757UnitsQuestion.MayBeOpen`): its blind defuel YES (400,648) lands 14 px from that question's YES, so a unit mismatch, an unread unit or an unanswered question refuses before any tap. Full: docs/invariants/b757.md#b757-4
- [B757-17] Write BlueBird's settings files only via `Bbs757SettingsFile.Save` while `Bbs757SimGuard.SettingsWritable` holds (no simulator process; a failed check is not writable): one value's bytes, verified, replaced atomically; never create the files; only values BlueBird stores, planned by `Bbs757EfbSettings.WritesFor`. Full: docs/invariants/b757.md#b757-17
