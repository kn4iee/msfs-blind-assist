# BlueBird 757-200 rules

Loaded when Claude reads matching code. Background: docs/b757.md. Full text of each rule: docs/invariants/b757.md.

- [B757-1] Never read or register the stock `BRAKE PARKING POSITION` on the 757: it read 0 with BlueBird's brake set (measured). The parking brake is `L:B757_FC_PARK_BRAKE`: the Control stand toggle and the status row `Bbs757Readouts.ParkingBrakeKey`. Full: docs/invariants/b757.md#b757-1
- [B757-3] Never step the MCP speed one `K:AP_SPD_VAR_INC/DEC` per knot in one burst: BlueBird speeds a burst up (events 1-10 move 1 kt, 11-25 2 kt, then 5 kt; measured). Plan it with `Bbs757Mcp.SpeedBursts` and correct in bursts of at most `Bbs757Mcp.LinearBurstMax`, each `Bbs757Mcp.SpeedBurstGapMs` apart. Full: docs/invariants/b757.md#b757-3
- [B757-17] Write BlueBird's settings files only via `Bbs757SettingsFile.Save` while `Bbs757SimGuard.SettingsWritable` holds (no simulator process; a failed check is not writable): one value's bytes, verified, replaced atomically; never create the files; only values BlueBird stores, planned by `Bbs757EfbSettings.WritesFor`. Full: docs/invariants/b757.md#b757-17
- [B757-18] A 757 tablet press goes through `Bbs757EfbPressRunner`: re-read, relocated and tapped, never on a stale read; a page control only inside its clip's top and bottom (`TapPoint`), after a `DragFor` drag, or not at all; a tap or drag start under the keyboard (`UnderKeyboard`) puts it down first, once settled. `PageUnchanged` skips top bar and notices. Full: docs/invariants/b757.md#b757-18
- [B757-19] Never add a refusal to a 757 tablet press (the owner's ruling of 2026-10-29): the window taps what the pilot pressed, REMOVE ALL, the presets, SAVE/LOAD and the AIRAC page's UPDATE/REMOVE included. Only `Bbs757EfbPressRunner`'s precision checks (where the control is now, whether its tap is still wanted) may stop a tap. Full: docs/invariants/b757.md#b757-19
- [B757-20] A tablet Settings row press is judged by the row's `Bbs757EfbSettings` key in BlueBird's files (`Bbs757EfbSettingsMatch.SettingFor`), a row matching no catalog entry by the page alone, never a key; a slider's choices are the catalog's, in order (`Bbs757EfbSettingsMatch.ChoicesFor`); a two-choice list says nothing once set (`ChoiceSwitchAsync`). Full: docs/invariants/b757.md#b757-20
- [B757-21] Never offer the EFB colors theme as a choice in either 757 EFB window (the owner's rulings, 2026-10-30): the reader reads only Dark blue. The tablet window shows a text note (`Bbs757EfbSettings.ThemeNote`, `Bbs757EfbElements`); the settings window, in a read-only box, and writes only Dark blue (`ui_theme` 0), through one button (`BBS757EfbForm`). Full: docs/invariants/b757.md#b757-21
- [B757-22] Name a tablet element only from BlueBird's structure (`Bbs757EfbModelReader`): name parts, index rows, the one touching label, the settings row's label, `Bbs757EfbPageRules`; a text box or drop-down by title, row label, prompt face, then own name, never a touching label. Section and current tab: the one selected (none or two: none). Never guessed. Full: docs/invariants/b757.md#b757-22
- [B757-23] BlueBird's keyboard keys (`Bbs757EfbScreenModel.Keyboard`, `Bbs757EfbKeyboard`) read visible whether it shows or not: never a window element, never proof it is up. Up is `Bbs757EfbScreenModel.KeyboardState` (the keyboard app's bytes); no key is tapped unless it shows shown and ready (B757-29). Full: docs/invariants/b757.md#b757-23
- [B757-24] Write a tablet tree fixture only through `Bbs757EfbTreeScrub`: it replaces the SimBrief ID, Hoppie logon code and SayIntentions ACARS key (saved and in the AIRAC text boxes, by exact name, not a suffix), every flight plan value, the Operating FP's text and PERF calc's text boxes with made-up ones, by node name. Never commit a real one. Full: docs/invariants/b757.md#b757-24
- [B757-25] A tablet drag eases out to a stop (the agent's `A.drag`: each step shorter than the last, the last a 400th of the drag): BlueBird's scrollbox flings on by about the square of the last step when the button comes up, hold or no hold. Never drag in even steps. Full: docs/invariants/b757.md#b757-25
- [B757-26] A tablet scrollbox's scroll is its content offset, the layout's `ScrollboxOffset` (+0x134 in this build, tablet pixels: 0 at the top, content less viewport at the end), read by `Bbs757EfbMemory` (`ReadScroll`); never the scrollbar thumb at +0x158, which stops short of the content's end. Full: docs/invariants/b757.md#b757-26
- [B757-27] Choose from a tablet drop-down only through `Bbs757EfbPressRunner.ChooseAsync`: its face tapped unless open, the entry's row tapped where the list shows at least `MinShownPx` of it (else not chosen), never dragged (an open list scrolls by no input: measured), confirmed from a fresh read, silent once it took; never by writing memory (WASM-1). Full: docs/invariants/b757.md#b757-27
- [B757-28] A set from the 757 tablet window acts only once it settles: `Bbs757EfbCommandQueue` waits `SetSettleMs` (300 ms) for a newer set of the same element and runs the last. Never run every queued set: NVDA's arrows through a choice list or slider fire one per step, and each would tap the tablet (a drop-down: two taps and two waits). Full: docs/invariants/b757.md#b757-28
- [B757-29] Type on the 757 tablet only through `Bbs757EfbPressRunner.TypeAsync` on fresh reads (B757-18): a character on no key stops it before any tap (keys unread: before any key); no key until `Bbs757EfbScreenModel.KeyboardState` reads shown and ready, none but the down key or keypad OK (its end) unless typing into that field; read back; never logged. Full: docs/invariants/b757.md#b757-29
