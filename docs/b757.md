# BlueBird 757-200

BlueBird Simulations' 757-200, package `bluebirdsim-aircraft-757-200` (release 0.1.0). Profile
"BlueBird 757-200", code `BBS_757`, chosen from the Aircraft menu like every profile. Rules:
`.claude/rules/b757.md`. The investigation, the spec and the plans are under `docs/b757/`.

## Where the code is

- `Aircraft/BBS757Definition.cs` (identity, variables, panels) and `BBS757Definition.Interaction.cs`
  (panel writes, the BBS Nest warning, hotkeys).
- `Aircraft/BBS757/`: `Bbs757ControlMap` (the map loader), `Bbs757Rpn` (the calculator strings),
  `Bbs757Write` (what a pick sends, pure), `Bbs757Nest` (the process check).
- `Forms/BBS757/` (the Ctrl+M monitor manager) and `MainForm.BBS757.cs` (menu entry, windows,
  their teardown on an aircraft switch).
- `HotkeyGuides/BBS757_Hotkeys.txt`.

## The control map

`MSFSBlindAssist/Resources/bbs757_control_map.json` is generated from the installed package by
`tools/b757-gen/generate_b757_map.py` (`python -I tools/b757-gen/generate_b757_map.py`, which finds the
package in the Community folder; curation in `tools/b757-gen/curation.json`): every regular control's
node, section, panel, label, named positions and the vendor's click code, plus the read-only status
rows. Regenerate it after a BlueBird update, never hand-edit it. It is embedded and loaded once.

Each control becomes one OnRequest L:var keyed by its node; buttons and held buttons render as
buttons, everything else as a combo of its positions. The status rows (APU state, master warning and
caution, the AC bus power sources, APU speed, cabin altitude) are the Status section's display; the
announced ones have Ctrl+M rows.

## How it writes

Every write replays the control's own click code through the MobiFlight calculator with a unique
prefix: a toggle, guard or select presses once when it is not at the pick; a switch steps by position;
a switch with no click code is written through its state var. A pick is acted on 300 ms after the
last row the pilot arrows onto, from a fresh read of the control; an unread or unknown reading sends
nothing. Before writing, the definition asks `CalcWriteCanLand` (it registers `MSFSBA_BRIDGE_PROBE`,
so the calc-path probe gives a verdict) and says "{label} unavailable" when nothing could land. A
button is pressed, held 200 ms (a held button its own time) and released, then "{label} pressed" is
spoken. 1.5 s after any write the control is read again, so its combo shows where it really is.

## BBS Nest

BlueBird's systems run only while BBS Nest (`C:\BBS Nest\bbs_nest.exe`, its own SimConnect client)
runs: without it the cockpit takes every switch and no system reacts. About a second after
connecting, switching to the profile or loading a flight, the app looks for the `bbs_nest` process
once and, when it is missing, says once: "BBS Nest is not running. The 757's systems will not
respond until it runs and the flight is reloaded." The check rides the end of the 1 Hz continuous
batch (`DeferredFlushWatchVariable` on `SIM_ON_GROUND`), which is delivered whether or not a value
changed, so a quiet cold-and-dark cockpit is not a reason to wait.

## CDU and EFB

Both CDUs' screens arrive as text on the simulator's Comm Bus (`BBS_CDU_DISPLAY_1`, `_2`), read
through the Coherent debugger in the hidden `BBSTablet` view; keys are held L:vars
(`L:B757_CDU_<1|2>_<KEY>`). BlueBird's tablet is drawn and clicked inside the aircraft's WASM, so the
"757 EFB" window operates it by scripted clicks at measured positions and confirms each step through
state the app can read. Both windows are being built in plan 01 (tasks 6 and 7); details in
`docs/b757/spec.md` §3.3 and §6.

## Not here yet

no circuit breakers (511 bitmask breakers are left out of the map), and the speed brake lever is not
in the map. MCP value entry and the AI display reads arrive with plan 01's later tasks.
