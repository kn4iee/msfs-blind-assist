# BlueBird 757 EFB as One Window Implementation Plan (plan 18, added 2026-10-29)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Task 0, the claim, is the controller's own, done before Task 1 is dispatched. Tasks marked [controller] or [owner] are never dispatched to an implementer.

**Goal:** Shift+T opens one 757 EFB window that is BlueBird's tablet: read through OCR, every control pressable where the reader found it, the app's few extras on the page they belong to, nothing offered that the tablet is not showing; with no simulator running, it opens BlueBird's settings instead.

**Architecture:** The tablet reader (plan 11, PaddleOCR since plan 17) becomes the EFB. The shared accessible EFB window (`FbwEfbForm`) stays; `Bbs757EfbBridge` keeps the session (pop-out, mirror, capture, reads, commands) and executes presses decided by small pure units: `Bbs757EfbPress` (find the control again, tap or not, what is said), `Bbs757EfbTopBar`, `Bbs757EfbNotices`, `Bbs757EfbSettingsMatch` and `Bbs757EfbExtras`. The classic window keeps only its Settings content; its Flight page and every blind tap sequence go.

**Tech Stack:** C# 13 / .NET 10 Windows Forms (WebView2 through `FbwEfbForm`), PaddleOCR PP-OCRv6 small through RapidOcrNet, xUnit, ES5 agent.

**Spec:** the owner's design of 2026-10-29, kept locally (`docs/superpowers/specs/2026-10-29-b757-efb-unified-design.md`, git-ignored by the owner's choice); every decision and value a task needs is copied below. Evidence: `docs/b757/evidence/tablet-presses.md` (Task 1 commits it). Background: `docs/b757/evidence/flight-11.md`, `tablet-ocr.md`, `efb-settings.md`; `docs/b757.md` "The 757 EFB window"; rules B757-2, B757-4, B757-17, OCR-1 to OCR-5.

## Review Focus

- **A notification drops over the control between the read and the press:** the fresh capture differs, the control is found again, and when it sits under the panel it is gone: nothing is tapped and "{label} is no longer on the tablet." is said, never a tap on the panel (Task 5 test `Relocate_never_takes_a_control_with_other_words`).
- **A switch pressed when the tablet already shows the wished state** (it changed since the read): no tap, nothing said (Task 5 test `A_switch_already_as_wished_needs_no_tap`).
- **A Settings label OCR misread:** no catalog match, so the press is judged by the page alone and never by a wrong key (Task 4 test `A_label_matching_no_catalog_entry_is_not_judged_by_the_file`).
- **The same notification words twice** ("Chocks attached." at 12:06Z and again at 12:09Z): spoken both times; one entry still showing at the next read is not spoken again (Task 3 test `A_notification_is_spoken_once_per_appearance`).
- **IMPORT FROM SIMBRIEF, then START BOARDING a minute later:** the boarding part joins the running watch and is judged from its own start; fuel-only never says boarding has not started (Task 6 test `Boarding_added_later_is_judged_from_its_own_start`).
