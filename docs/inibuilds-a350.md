# iniBuilds A350 Airliner

> **Read this when:** working on the iniBuilds A350 (-900, -900 ULR, -1000): its panels, the WASM display reader, the KCCU/MFD, the ECAM, the OIS/EFB, or re-deriving addresses after an A350 update.

Measured live on 26 October 2026 against **A350 1.2.7** (package `inibuilds-aircraft-a350`, released 23 October 2026) in MSFS 2024, A350-900 powered at VCBI. It builds on the 3 October 2026 investigation of 1.2.6 (`development/a350-investigation`), whose method this aircraft depends on.

## The reader: running the A350's own draw code

Every A350 display except the OIS, FAP and printer is a WASM gauge drawn with NanoVG; the Coherent DOM of those views is empty (`WasmInstrument`). The reader:

1. **Copies the A350's linear memory**, read-only (`OpenProcess(QUERY_INFORMATION | VM_READ)`, `ReadProcessMemory`). Locate the allocation by its anchors (`INI_MCDU{}_ENTER`, `INI_MCDU_OPTION`, `INI_FMC_PAGE1` at their data-segment offsets inside the 4 GB+ reservations of `FlightSimulator2024.exe`), then list ONLY that allocation's regions (`VirtualQueryEx` from its base, about 10 regions) and read them back-to-back into one preallocated buffer: 37.7 MB in about 8 ms.
2. **Runs the A350's own `Draw()`** of the wanted gauge on that copy, in a WASM runtime, with the module patched so NanoVG reports what it draws.
3. **Rebuilds the screen** from the reported text, colour, transform and element records.

Nothing is written to the sim and the installed module is only read; the patched module and its compiled cache are built on the user's machine from their own copy and never shipped.

**In MSFSBA** (`MSFSBlindAssist/Aircraft/A350/Display/`, ported from the prototype in `tools/a350-probe` and checked against it on one memory copy, gauge by gauge): `A350WasmModule` reads the module by name, `A350ModulePatcher` builds the scratch module (`patch2.py`'s hooks, plus the allocator answers of [A350-10], which the prototype lacks), `A350ModuleFacts` re-derives the vtables and anchors, `A350ModuleCache` compiles it once per A350 version and patch version under `%LOCALAPPDATA%\MSFSBlindAssist\a350\<sha256>-p<version>.cwasm` [A350-11] (about 15 s; then about 0.3 s), `A350MemoryReader` locates (about 1.2 s) and copies (8-20 ms) the A350's memory, `A350DrawEngine` draws (a round of CTR, both EFIS and the MFD about 70 ms, mostly restoring the copy before each gauge), `A350DrawLayout` reads rows with their colours, and `A350DisplayService` runs it all on one worker thread, started by MainForm while the A350 is active. `A350Probe` modes `patch`, `snapshot`, `draw <copy|live> Gauge[#n] …` (xy.mjs's format; `A350_DRAW_JSON=<dir>` saves captures as fixtures) and `service` exercise each layer.

**Hardening (review 2026-10-29).** The engine's name tables are bounded (4,096 names, 1,024 sim asks), so a torn copy cannot grow them without end. A copy clips at 4 GB, reads in pieces of at most 1 GB, clears a region that has gone since the last copy (`A350MemoryRegions`), and its buffer grows geometrically. Any error out of a draw, not only a trap, makes the next draw start a fresh instance. `nvgReset` resets the fill to white as well as the transform; drawn on two saved 355 MB copies with and without that change, every gauge read the same texts in the same colours. `nvgTransform`, never seen in 1.2.7's draws, is logged once, as positions after it would be wrong. The compile cache builds one module at a time (`BuildGate`), writes under a unique temporary name and moves it into place, deletes a write left over an hour, and keeps the latest other patch version of the same module, so the app and a probe built from different patch versions do not recompile each other's on every start [A350-11]. A cache it cannot write is tolerated: the module then compiles at each start, and every compile says "A350 displays getting ready".

**Traps.** About 40% of fresh copies were torn for the EFIS and MFD draws (they read out of bounds; the CTR draw never did in testing). Most of those traps were the A350's own allocator walking torn free lists, now answered by the engine [A350-10]: on two 355 MB copies saved in flight, 7 of 8 draws trapped before and none after. A trap is the capture's error; the engine then starts a fresh instance, since a trap leaves the wasm globals mid-call, and the service retries once on a new copy. The exe must not be CET-compatible, or a trap kills it [A350-9].

**Tearing.** A copy that spans A350 frames is inconsistent. Walking all 25,000 process regions while reading (0.5 s) gave empty or garbage WD lists in half the draws and once trapped `dlmalloc`. The 8 ms allocation-only copy gave 8 of 8 consistent draws. As the A350's memory grows over a flight (66 MB fresh, 495 MB after hours), a copy takes longer (650 ms at 495 MB) and tears again; the allocator no longer cares [A350-10], but the A350's own data can still be torn (a flight plan list once). Still treat a trap as a torn copy and take another.

**Runtime.** Wasmtime for .NET (`Wasmtime` 48.0.2, net10.0): the 69 MB patched module compiles in 10 s with a 1.4 GB peak, once per A350 version; `Module.Serialize` caches it (118 MB), and the cached start takes 125 ms and 357 MB. Draws take 1-15 ms (CTR first draw 11 ms, then under 1 ms; MFD 2 ms).

### The patch (all found by name: the module keeps its full name section)

Each hook prepends a call to WASI `path_readlink` (an import never used while drawing) with a magic number as the sixth argument:

| Function | Magic | Reports |
| --- | --- | --- |
| `nvgText` | 0x7E57 | string, end, ctx, x, y |
| `nvgFillColor` | 0x7E58 | ctx, colour pointer (four f32) |
| `nvgSave` / `nvgRestore` | 0x7E59 / 0x7E5A | ctx (fill and transform stack) |
| `nvgTranslate`, `nvgScale`, `nvgRotate` | 0x7E5B-0x7E5D | ctx and the arguments |
| `nvgResetTransform`, `nvgReset`, `nvgTransform` | 0x7E5E-0x7E60 | ctx |
| `DrawFrame`, `DrawWideFrame` | 0x7E61 + 0x7E62 | rectangle, then colour (wide flag set): the ECAM selection box is a cyan wide frame |
| every `<Class>::draw(NVGcontext*, bool, int)` UI element (40 classes in 1.2.7) | 0x7E65 | element pointer, ctx, class index: rectangle at element +4/+8/+12/+16 |
| `nvgScissor` / `nvgResetScissor` (left alone where a version lacks them) | 0x7E66 / 0x7E67 | ctx and the clip's rectangle / ctx: the clip in force, saved and restored with the state; a text drawn outside it is `Clipped` (live 2026-10-30: the PFD's tapes clip through `setClipArea`, and their labels and the held selected altitude scrolled through the FMA strip) |

The allocator is answered, not reported [A350-10]: the call is followed by `return`, so the function returns the engine's answer and its own body never runs. A function a version lacks is left alone.

| Function | Magic | The engine answers |
| --- | --- | --- |
| `malloc`, `dlmalloc` | 0x7E70 | size: a block from the head room above the copy |
| `calloc` | 0x7E71 | count, size: a cleared block |
| `realloc` | 0x7E72 | pointer, size: a new block holding the old one's bytes |
| `internal_memalign` | 0x7E73 | alignment, size: an aligned block (1.2.7 dropped dlmalloc's `mstate` argument) |
| `posix_memalign` | 0x7E74 | out pointer, alignment, size: writes the block, returns 0 (48 when the head room is used up) |
| `free`, `dlfree` | none | a bare `return` |

Exports added: `CTR::Draw`, `EFIS::Draw`, `FCU::Draw`, `HUD::Draw`, `ISIS::Draw`, `RMP::Draw`, `BAT::Draw`, `MFD::Draw`, `FMGS::Draw`, `SFD::Draw(int)`, `SND::Draw(int)`, `Systems::Draw`, `nvgBeginFrame`, `nvgEndFrame`. Texts must be placed with the tracked transform: the CTR draws the SD and WD with `nvgTranslate`, so raw positions overlap.

### Questions the draw code asks the sim

A draw makes a few sim calls, which the stubs must answer:

- **L:vars by id** (`fsVarsNamedVarGet`): most are `CustomVariable` objects on the heap, laid out `{u32 id, std::string name, f64 lastValue at +16}`. Scan the copy for that shape (1,357 found, 100 ms) and answer from the cached value: the copy is self-sufficient. `VariablesEnum` names use the id array at 1336752.
- **A: vars by name** (`get_aircraft_var_enum` / `get_units_enum` / `aircraft_varget`): the FCU and SFD ask `KOHLSMAN SETTING HG:1..3`, the EFIS and CTR `TURB ENG N2:1..2`. Supply them from SimConnect.
- **Calculator strings** (`execute_calculator_code`): the EFIS asks `(A:NAV IDENT:1..2, String)` and `(A:ADF IDENT:1..2, String)`.

Unanswered, those come back 0: QNH 0000 on the FCU, VHF 0.000 on the RMPs.

## Operating the displays: the sim's own mouse route

The gauge host views forward mouse input with `Coherent.call("WASM_MOUSE_MOVE" | "WASM_MOUSE_DOWN" | "WASM_MOUSE_UP" | "WASM_CLICK", guid, x, y, button)` (`wasm-sim-canvas`). Evaluated in that view over the debugger, these reach the A350: the gauge's `GaugeData` mouse position (+48/+56, f64) updates and the gauge's `MouseEvent` runs. The 1.2.6 finding that they "do not reach the A350 gauges" came from the cursor not being on that screen: the ND handles mouse input only while `INI_CPT_CURSOR_SCREEN` is 1, the MFD while it is 2. Move the cursor with the KCCU keys `INI_MCDU{1,2}_ND` / `_MFD`.

Verified live: a move put the captain MFD pointer exactly where sent; a move-down-up-click on ACCEPT dismissed the crash-report dialog; clicking the FROM box focused it; `INI_MCDU1_V`, `_C`, `_B`, `_I`, `_ENTER` entered VCBI, and TO WMKK made DEPARTURE available and CRZ FL a required (amber) box; a click on the aircraft symbol opened the ND pop-up (P.POS, DIR TO), and a click on empty map closed it; the first officer's MFD takes x + 836. No write into the sim's memory is needed, so the investigation's pointer request is not used.

## The E/WD in MSFSBA (live 2026-10-27)

`A350PfdMonitor`'s tick draws the CTR first on its memory copy and hands it to `A350EcamMonitor` (about twice a second while the A350 is active); `A350Ewd` cuts the capture into the engine block, the warning display (WD), the SD page and its permanent data line; `A350EcamAnnouncer` speaks each WD line that appears, with each colour run's colour ("SURV TCAS STBY, amber"), once two reads agree. The first agreed read is a silent baseline; an unpowered CTR draws nothing, so a cold-and-dark power-up speaks the whole list as it comes up. Speech sits behind one Ctrl+M row, `A350_ECAM_WD` ("ECAM E/WD call-outs"), which Ctrl+E flips; Alt+E opens `FbwEwdWindow` over `A350EwdText`.

How the WD draws, measured on a power-up at VCBI (BAT 1, BAT 2, GPU from the OIS, EXT 1, EXT 2):

- Texts are placed at their baseline. Rows of only dots are the collapsed-procedure marks and are skipped; a dot leader inside a line ("APU MASTER SW ......OFF") reads as a colon.
- The ECAM cursor is a cyan wide `DrawWideFrame` around a row; an action box is a 15 x 20 `DrawFrame` left of a row, cyan while to do. Both belong to the row whose glyphs they overlap most. Airbus colours carry the state: an action done turns white (APU MASTER SW: OFF white with the APU off; cyan again once APU MASTER was switched on with APU EMER SHUTDOWN active).
- The power-up order: the SD shows "SAFETY TEST IN PROGRESS (MAX 30 SECONDS)" (green) for about 30 s, then the WD lists FWS FWS 1+2 & CPIOM FAULT with its cyan instructions and the amber FUNCTIONS NOT AVAIL list (12 lines), and about 35 s later the boot-up alerts (SURV SYS 1 FAULT, F/CTL SLAT SYS 1+2 FAULT, APU EMER SHUTDOWN, ELEC BAT EMER 1 and 2 OFF, SURV TCAS STBY). Batteries alone leave the CTR dark.
- The first draw of a gauge on a fresh Wasmtime instance draws only the WD titles; the engine throws that warm-up draw away.
- The engine block's labels (N1, EGT, N2, FF) are textures: its numbers read unlabelled until they are mapped by position (a capture with engines running).

## The PFD and FMA in MSFSBA (live 2026-10-27)

Each EFIS draws its PFD on its outboard half, as in the cockpit: EFIS#0 (the captain's, panel.cfg's parameter L) has the PFD on the left half and the ND on the right (x >= 836), EFIS#1 (the first officer's, R) the other way round. `A350DrawEngine.InPanelOrder` numbers them by that parameter, read from the object (+8 points at the gauge's data, whose +16 is the string), never by address: live 2026-10-30 the first officer's object sits below the captain's, and until then index 0 was the first officer's, so "Captain ND" followed the first officer's knobs (the same goes for the RMPs, no parameter, R, C, and the HUDs) (`A350DrawLayout.EfisPfd(side)`). `A350Pfd` reads a PFD by area in its own coordinates: the FMA strip (y < 125: five columns of up to three rows, read in flight 2026-10-28), above the speed tape while off its scale the speed target (x 153, y 174: magenta managed, the V2 before takeoff; cyan selected) and V1 under it (cyan, x 129, y 207; live 2026-10-28, "Speed target: 148, magenta", "V1: 142, cyan"), the speed "30 knots or less" while the tape rests on its floor, the altitude from the tape's label and the drum at the window (y 389), the selected altitude (cyan), QNH, the radio altitude under the aircraft symbol, the heading from its scale (index at x 359, 7 px a degree, calibrated against 219 degrees), and everything else as drawn (flags, the T.O THS FOR line; a two-line message there joined into its row: "T.O THS, white; OUT OF RANGE, red" while the trim is not yet at PERF's THS). The tape and drum labels are never read as text. `A350PfdMonitor` draws the captain's EFIS each tick for the FMA call-outs (`A350FmaAnnouncer`: two agreed reads, silent baseline, "FMA vertical: SRS, green", "FMA engagement clear", one Ctrl+M row per column) and the first officer's while its status display reads it (and every 15 s besides); the Displays section's Captain PFD and First Officer PFD panels read each side's latest draw. Live: FD off then on was heard as "FMA engagement clear", then "FMA engagement: 1 FD 2, white" (`A350Probe pfdlisten`). The heading scale's sprites are read by their atlas place (`PFDA350Elements.png`): the selected heading bug (811, 333; shown in HDG, gone in LOC) and the track diamond (296, 281), "Selected heading: 031, cyan" and "Track: 034"; a target off the scale is the cyan number beside it (the bug then waits at the scale's edge). The flap indication at the bottom reads "Flaps: 3, cyan" (cyan while moving, green once there). The baro never takes an altitude tape label passing through its area.

A text drawn outside the clip is not read (`DrawnText.Clipped`, from the scissor hooks): the altitude tape's labels and the selected altitude held at the screen's top scroll through the FMA strip over its fourth column, and on the OMDB ILS 12L final (2026-10-30) they made the column re-read four times in 15 s ("LAND3; DUAL; 3000", "LAND3 3000; DUAL"). The selected altitude's readout above or below the tape is white after an autoland with the APs off, and is read in its own colour. In 1.2.7 the FMA never draws LAND, FLARE or ROLL OUT: through an autoland to a stop it shows G/S and LOC (two live autolands, 2026-10-30), so MSFSBA has none to say.

ILS (flown live on the VCBI ILS 04, 2026-10-27, LS on, LOC engaged, G/S armed): the LOC and G/S scales and diamonds are sprites of `Data/Textures/PFD/PFDA350Elements.png`, found by drawn size (LOC scale 294 x 35 under the attitude, G/S scale 12 x 294 beside it, diamonds 40 x 28 and 27 x 39). Their dots are 70.25 px apart around a centre 146.25 px (LOC) and 146.75 px (G/S) into the scale, so `A350Pfd` reads each deviation in dots where the aircraft is, as the A380 words it ("Glideslope: 1.4 dots above glideslope", "Localizer: on the localizer"), and "off scale" while the scale is drawn without its diamond (beyond 2 dots). Nothing is read while LS is off. The LS block in the lower left reads as one line, "LS: IKW 109.90, 7.8 NM, magenta" (the frequency is drawn as "109." and "90"); it appears a few seconds after LS is pushed with the ILS in range. Two things seen with no flight plan in the FMS: G/S stayed armed through the beam and never captured, and TOGA thrust gave no go-around mode; both are expected to need an approach in the F-PLN (to verify on the full flight).

**Flashing lines** (`A350FlashingLines`, live 2026-10-30). The A350 flashes a line by leaving it out of every other draw: QNH above the transition altitude (read at FL400: "QNH: 1013, cyan" on most reads, nothing on the next), STD below the transition level, an FMA mode. A single read cannot tell, so the two PFD status displays remember: a line of the FMA, the baro or the flags that comes back within 4 s of leaving reads ", flashing" and is held in its place while it is out; one that simply goes is gone at once. The flash is in sim time (at 4x it beat with half-second reads into runs of several alike), hence the window. The tapes' figures come and go by themselves and are not followed.

**The PFD's flags** (`A350PfdFlagAnnouncer`, gap 134, 2026-10-30). What fits no area of the PFD is where its flags and warnings land: the module's strings there include PULL UP, SINK RATE, GLIDE SLOPE, RWY TOO SHORT, MAX REVERSE, MAX BRAKING, AUTO BRK OFF, SPD BRK AUTO EXT; seen drawn: PULL UP (x 359, y 400, green and then red over it), ATT red, the T C A S letters one under another (x 700, y 480 to 563, amber, now one word), DH amber (x 358, y 546), AUTO BRK OFF amber, DECEL green, T.O THS OUT OF RANGE. No list of them: a line with a red or amber part, or nothing but words in white or green, is said; a figure in another colour (the T.O THS FOR row, the magenta ILS) stays in the status display. Said on 2 of the last 4 reads, because a flashing flag never agrees with itself on two reads in a row and one torn read must say nothing; new again only after 6 reads without it. One Ctrl+M row. The FMA's own messages (T/D REACHED, USE MAN PITCH TRIM, MAN PITCH TRIM ONLY, CHECK APPR SELECTION...) are its columns' call-outs.

**Low memory** (`A350MemoryWarning`). A long A350 flight grows the sim's commit 17-35 GB an hour, and at the commit limit the sim dies with no warning. Below 10 GB of free commit the reader says so once, below 5 GB once more; 12 GB arms it again. It informs and does nothing else. One Ctrl+M row.

## The other displays in MSFSBA (live 2026-10-27)

## The MFD window in MSFSBA (live 2026-10-27)

## The RMPs in MSFSBA (live 2026-10-28)

Each RMP is a pedestal panel (Captain RMP, First Officer RMP, RMP 3, in the manual's pedestal order) of its 64 input events and a STBY RAD NAV row (`A350PanelLayout.Rmp`): the keypad, the line select keys, the activation keys, the six page keys, eleven microphone keys (lit when theirs is `INI_RMPn_TRANSMIT_CHANNEL`), their volume knobs and receptions (the knob's push-pull, `INI_RMPn_m_RECEIVE_SEL`), brightness, RAD NAV and INT/RAD. Each key is one Set of 1: its set code writes an `RMP_CPT_*_KEY` L:var that the aircraft consumes within a frame or two (read back 0 at 30 ms), and repeated presses of one key all land (the cockpit's click calls the key's `_Toggle`, which flips the latched position; the Set's L:var write is what presses). iniBuilds names the activation keys' L:vars `LSK` and the line select keys' `RSK` (left and right of the screen). Keys must arrive a frame or more apart: 4 3 2 1 sent in a burst landed as 3412 (the aircraft reads one frame's keys in its own order); one at a time they landed in order. The keypad's squawk entry is a state the screen does not show (SQWK then digits landed as 2002 for a typed 2000), so a squawk is set with the stock `XPNDR_SET` (BCD), as the A380 window does: the A350 keeps `TRANSPONDER CODE:1` and the RMP screens in step (8192 showed SQUAWK : 2000). iniBuilds 1.2.7's RMP draws only the VHF page: HF, TEL, SQWK, MENU and NAV leave the screen as it was.

**The keypad's selected line** (read from the A350's memory, 2026-10-28: one 12-byte string per line, six characters at most, already normalized: 2 7 2 is kept as "1272", 8 7 as "1187"). The RMP has a selected line, and its screen shows neither the selection nor the entry; the cyan frame and colour on VHF1's standby are the transmitting radio's, not the selection. Digits and CLR edit the selected line's entry (one CLR deletes one character; on an empty entry it does nothing). That line's line select key loads the entry as its standby, or refuses it, emptying it either way; another line's key only selects that line, emptying ITS entry, and loads nothing. So 2 7 2 typed with line 1 selected, then LSK2, loads nothing, and the 1272 waits on line 1 for the next LSK1: the manual's order is select the radio (its line select key), type, press it again. `A350RmpEntry` starts each entry with eight CLRs (emptying whatever line is selected) and the line's own key (on the selected line it loads the now empty entry, which does nothing; on another it selects it), so it works whatever the RMP had selected; picking another line mid-entry deletes it and types it again there. Live through the real window (`A350Probe rmpwin`): 123.450 into VHF3, an entry begun on line 2 and moved to line 1 (122.500), 999 refused ("standby unchanged"), the departure set-up (VHF1 Ground 121.900 with Tower 118.700 in standby, VHF2 ATIS 127.200 with Approach 120.900). Never test the keypad through the simconnect MCP: its byte-identical strings are dropped or land with the next one, leaving digits in a line's entry that nothing shows (they cost a night's misdiagnosis); `A350Probe rpn`, `keep` and `rmpwin` send through MSFSBA's own unique path, and `memfind TEXT` / `memread LINEAR[:COUNT]` read a live copy (type a distinctive entry, find it, then watch it).

Ctrl+Shift+R opens `A350RmpWindow` (A380 parity): the chosen RMP's screen as lines (`A350GroundDisplays.ReadRmp`: the background monitor's latest draw, or a fresh one after a key; `A350ShownCapture` never shows the monitor's draw from before a fresh one, which flipped the list back and spoke the old line again). Ctrl+1/2/3 picks the line; digits are keyed into the keypad in order, 150 ms apart, the first one selecting the line (`A350RmpEntry`); Backspace deletes the last (CLR) and says what is left, as the RMP cannot show it. Enter presses the line's line select key and reads the line back ("272: standby unchanged" when the RMP refused it or it was there already); Alt+1/2/3 presses the activation key and reads the line back. An entry left behind by an activation or page key, another RMP or closing is deleted first ("272 cleared"). Alt+V/H/L/N/U press the VHF, HF, TEL, NAV and MENU page keys and read what changed ("HF page: screen unchanged"). Alt+T a squawk (four digits 0-7, set on the fourth).

**COM 1 from outside the window** (`TuneCom1Own`, the Surroundings window's Enter and Shift+Enter; live 2026-10-30, 118.705 standby, then 121.900 active): `A350Rmp.ComTuningKeys` presses RMP 1's VHF page, empties its entry, selects line 1, types the six digits, loads, and swaps with the activation key if active; `A350RmpPage.Vhf1Hz` reads the screen back. The stock events do nothing here (COM AVAILABLE:1 reads 0).

**The other pages** (live 2026-10-30, `A350RmpPage`: every page is drawn, fixtures `rmp_*`). `INI_RMP_PAGE_{CPT,FO,OVHD}`: HF 0, VHF 2, VHF's others, MENU 10, SQWK 11, NAV 12; TEL changes nothing. The side keys sit on three rows (y about 160, 340, 516); `AIRLINER_RMP_LSKn` is the module's right-hand key, `AIRLINER_RMP_ADKn` its left-hand one. MENU's second right-hand key opens DATALINK ROUTER (INIT, COM STATUS, VHF PROVIDER, each a right-hand key; RETURN the third left-hand one). The NAV page's LS and VOR are grey and take no press until `L:INI_{CPT,FO,OVHD}_RADIO_MODE` is 1 (`RMP` +12 to +172, and globals 1375498/9 the FMS sees). **Nothing in the package writes that variable:** only `RMP::Startup` names it and `sound.xml` plays `rmp_square_button` on it; every RMP key and selector was pressed with it watched and none moved it. iniBuilds' FAQ documents a STBY RAD NAV key, so the row and the window's line write it (documented = doable, `A350Rmp.StbyRadNavKey`). With it on: right-hand key 1 opens the LS page, 2 the VOR page. There a left-hand key starts the frequency (it shows `!!!.!!`) and a right-hand key the course; the digits go in and the field takes them as they complete, so `A350Rmp.TuningKeys` sends the whole entry at once. VOR 1's frequency and course reach stock `NAV ACTIVE FREQUENCY:1` and `NAV OBS:1` at once. The LS page's did not reach stock NAV 3 on the ground (it read 110.5 throughout; the page keeps what was typed). Its GLS key stays grey.

## The draw code's own sim reads

A few things the draw code asks the sim directly (`aircraft_varget` / `fsVarsAircraftVarGet`), not its memory: engine N2 on the CTR (`TURB ENG N2:1/2`, Percent) and the baro settings on the EFIS and ISIS (`KOHLSMAN SETTING HG:1/2/3`). ## The SD in MSFSBA (live 2026-10-27)

The ECAM Control Panel's "System display page" status display (and Alt+E's "System display" section) reads the page shown through `A350SdPage`, and the permanent data line under it (TAT, SAT, flight time, UTC, GW, GWCG, FOB) through `ReadPermanentData`; a value drawn as several texts on two rows (UTC's colons sit lower) reads as one. The ENG page's start box (live, during and after a start): the igniter in use ("Engine 1 igniter: B") and, under each start valve, the start air pressure in PSI, whose unit is not drawn.

## Panels

`A350_Interior.behavior.xml` holds 696 input events (RMP 192, FCU 44, EFIS 38, ECAM 32, DISPLAY 30, ELEC 26, WXR 20, MAINT 17, OXYTEST 16, AIR/FUEL/ISIS 14, FCTL 13, …). It parses with the iniBuilds `behavior_xml.py` after rewriting tags that begin with a digit. Each event's set code writes `INI_*` L:vars directly (for example `INI_SEATBELTS_SWITCH`, `INI_BATTERY_1_SWITCH`, `INI_MIXTURE_RATIO1_HANDLE` for ENG MASTER 1), so a native L:var write operates the control; live: `INI_NO_SMOKING_SWITCH` 1 → 2 changed the takeoff memo's SIGNS line from done to outstanding, and back. Position names come from each control's own tooltip expression: some count from `.1` (`SIGNS_SEAT_BELTS.1` = ON is value 0), others from `.0` (`MAINT_ELEC_BAT_VOLTAGE_SELECTOR.0` = EMER 1).

MSFSBA writes a row with its own input event, `value (>B:AIRLINER_<id>_Set)`, on the calculator path (`A350WritePlan`). `tools/A350Probe` drives rows through MSFSBA's own definition and SimConnect path (`live <panel> [watched L:vars]` tries every position, reads back, restores, and logs the panel's lights and the watched variables that changed); close MSFSBA first. Probing the same path with the simconnect MCP's `execute_calculator_code`: each string lands only when the NEXT calculator string arrives, so a read straight after a write shows the previous write. Follow every probe write with a harmless unique string (`n (>L:MSFSBA_CALC_TEST)`) before reading back.

The Overhead, Glareshield, Instrument, Pedestal and Cockpit sections are offered; a section joins once each of its panels has been driven live (`IniBuildsA350Definition.CuratedSections`). The panels' lights come from the map's emissive rules (`A350PanelLamps`): a lamp belongs to the row whose id is the longest prefix of its node, reads On only while its rule holds and its bus's light power (`INI_AC_LIGHTS_FAILURE` / `INI_DC_LIGHTS_FAILURE`, 1 = powered) is on, and a legend that reads nothing but its own switch is left out.

A button row shows its state beside its name wherever the cockpit shows one (`TryDescribeControlState`, `A350ButtonStates`): a button with one light reads On or Off. A button with several reads its lit legends ("EXT 1: Available", "APU agent: Squib and discharged", "Green ENG 1 supply: Shut"), a master light's lower half reading On, and reads Off when none is lit. A button with no light reads the state it switches, as the FCU and EFIS show it: SPD/MACH (Knots, Mach), HDG-V/S / TRK-FPA, each baro unit (Hectopascals, Inches), each baro knob's push and pull (STD, QNH; on the A350 the push selects STD and the pull QNH, the A320's the other way round: live 2026-10-28, `INI_n_ALTIMETER_PUSH_COMMAND` put `XMLVAR_BaroN_Mode` to 3 and a second push left it there, the pull command back to 0), and each FCU knob's push and pull (speed and heading Managed or Selected, the heading Managed while NAV is engaged or armed: roll mode 1 or the window's managed dot `INI_FCU_HDG_DOT`, as on the ground before takeoff; altitude Managed while its managed dot shows; V/S Engaged while V/S or FPA is the pitch mode). Each row's label repaints when that state changes. Momentary keys with nothing to show (calls, chronos, tests, the ISIS keys, the RWY COND knob) read nothing. Checked live with `A350Probe labels <panel>` against the aircraft's own variables.

### Announcements

What changes on its own is spoken, as on the A380, and each spoken thing has its own Ctrl+M row in the A350 Monitor Manager (`A350MonitorManagerForm`, list `UserSettings.A350DisabledMonitorVariables`):

- **Switches.** Every switch, selector and knob row is Continuous and announced, spoken by MainForm's generic path with its row's words ("Seat belts: On", "BAT 1: Off"); the pilot's own pick is not repeated (the echo gate, [CORE-8]). Spring and press rows are not listed.
- **Lights.** The definition speaks them as the cockpit lights them, rule × bus light power (`A350LampBoard`), at a batch end in one netted sentence (`A350LampSpeech`, the iniBuilds A300's timings: 1.5 s gather, 3 s off-hold so a flash reads once, 2.5 s settle after a light power change). A light's first value is a silent baseline; three batch ends after a connect or flight load the lights still unread are seeded from the cache. The master caution and warning speak "on" once (the captain's upper legend, `MasterSpeakers`); the other six legends are echoes with no row. MASTER WARN flashes (about 0.5 s lit, 0.5 s dark), so it is read from a steady variable beside its legends: `INI_MASTER_WARNING_ACTIVE` for most warnings, and `INI_AUTOPILOT_DISCONNECT_LIGHT` for AUTO FLT AP OFF, which leaves ACTIVE at 0 (live 2026-10-30: read from the flashing legends alone it was said four times in 21 s); both hold 1 until the pilot's MASTER WARN press. A pressed button's own light is left to its label for 3 s (`PressedLampMs`).
- **Mutes.** A switch row is muted at MainForm's generic gate; a light inside the definition (`IsMuted`). A delivery that changes several lights (a light power flag, a shared input) is exempt from MainForm's mute wrap and checks each light's own row (`IsMuteWrapExempt`, [VAR-8]).
- **One light, two lamps.** Lamps both sides light from one rule (ECAM CLR, ATC MSG, AUTOLAND) are one light: the captain's speaks, without its side ("ECAM clear light on"), and the other is its echo, with no Ctrl+M row; a press of either side's button is the pilot's own (review 2026-10-29).
- **Blinks and the master lights.** A light that goes off and on again within the off-hold says nothing (a pending "on" waits while its off is held). The master caution and warning are steady: lit again after an off, each is a new "on", and a master press never quiets its relight.
- **The pilot's own presses** (review 2026-10-29, panels minor 3; [CORE-7]). A button whose label shows no state says "<name> pressed" once the press is made; one that shows a state is confirmed by its label, which the screen reader says. An encoder stepped with its increase and decrease rows says the value the cockpit then shows, once the steps settle (`A350FcuCallouts.StepSettleMs`, 400 ms, at the next batch end: a run of steps is read back once).
- **FCU windows** (parity 2026-10-29, as the iniBuilds A300 speaks its altitude window, in its own pull request). The altitude window and each side's baro speak on their own, in the A380's words (`A350FcuCallouts`): "Altitude 12000 feet"; "Captain altimeter 1013 hectopascals", "First officer altimeter 29.92 inches", "Captain altimeter standard", "Captain altimeter preset 1013 hectopascals". The other windows are the autopilot's to move, so the FMA says what changed. A change is staged to a batch end through the shared FCU call-out (`FcuValueAnnouncer`, [A320-22]), quiet through a load's settle; MSFSBA's own typed value is the echo of its window and says nothing; a unit button MSFSBA pressed is said by the button's label, not by the baro; a preset going out of view on STD is recorded, never said. - **IRS alignment** (parity 2026-10-29). ### Flying the A350 for a test

`tools/A350Probe rpn "code#ms;…"` sends calculator strings through MSFSBA's own sender with exact pauses, for timing the MCP's
round trips cannot pace. The thrust levers go straight to an angle written into `L:INI_TLA1_REQUEST` / `INI_TLA2_REQUEST`
(the cockpit's own lever-drag code writes it; the aircraft takes it and puts the request back to -1), so a flight test sets
CLB with `25 (>L:INI_TLA1_REQUEST) 25 (>L:INI_TLA2_REQUEST)`. The axis events (`K:THROTTLE1_AXIS_SET_EX1`) moved the lever only
part of the way per event. Put back on the ground with the gear lever still up, the aircraft sits on its belly until the gear
is down and it is placed again; a placement also lets the parking brake go, so set it again at once.

Flight test, live 2026-10-27, all through MSFSBA's own rows (`A350Probe keep`), placed at 12,000 ft and 250 kt: All thrust
levers to Climb, then the FCU A/THR button, engaged A/THR (N1 87 %, `INI_ATHR_LIGHT` 1); AP 1 engaged from the FCU; each
A/THR disconnect button put the A/THR light out and each sidestick takeover disconnected AP 1 (re-engaged between); typed FCU
speed and altitude with the knob's pull flew an open climb; the speed brake extended the spoilers (`INI_SPOILERS_OUT` 1,
"Spoilers 50 percent") and retracted; the gravity gear extension (cover, both guards, Down) let all three gear legs fall to
100 % with the gear lever still up; EMER DESCENT armed its function (the ARMED light) and disarmed it on a second press (the
automatic descent itself starts only on a depressurisation). Put a test's FCU targets back afterwards: a speed left at 100
knots from ground tests had the A/THR pulling idle in the air.

### Takeoff, flight phases and the T/D pause (live 2026-10-30)

`INI_flight_phase` (`A380FlightPhaseTransitions::UpdatePhaseTransitions`) runs 1 preflight, 2 takeoff, 3 climb, 4 cruise, 5 descent,
6 approach, 9 go-around, and leaving preflight needs SRS (`INI_PITCH_MODE` 1) on the roll. A takeoff without SRS leaves it at 1 for the
whole flight, which is what a flight on 2026-10-30 did: no pause at T/D and no T/D REACHED (`FMGSmessage_Pause_at_TOD::update` wants phase 4,
`INI_PAUSE_AT_TOD_ENABLED`, `INI_TD_IDX` set and `INI_TD_DIST_TOTAL` within `INI_PAUSE_AT_TOD_DISTANCE`), no ACTIVATE APPR on PERF, a managed
speed that stays on the cruise schedule, and `FCPC_F_SPEED` still the takeoff configuration's F (137 kt, the F on PERF T.O, against PERF APPR's
154 at 193 t; the PFD draws its F symbol from the same variable). Fly such an approach on selected speed and set flaps 3 and FULL by hand.

What arms it (`AP_LOGIC::INI_update_throttle_detents`), tried on the brakes with both engines running and flaps 2, read from the FMA and
`INI_AUTOTHROTTLE_ARMED`:

| Levers | FMA | Armed |
| --- | --- | --- |
| TOGA | `MAN TOGA`, `SRS` with `CLB` armed, `RWY` with `NAV` armed, `A/THR` cyan | yes |
| FLX, a FLEX temperature in PERF T.O | as TOGA, with `MAN FLX` and the temperature | by the code; not yet tried |
| FLX, no temperature | `MAN MCT` | no, no SRS |
| TOGA after a press of an A/THR disconnect button, or as the first thrust after a landing | `MAN TOGA`, no SRS, no `A/THR` | no: latched |

The latch clears with a press of the FCU A/THR button; nothing reads different at idle (`INI_AUTOTHROTTLE_ARMED` stays 0 until the levers move).
`INI_EWD_FLIGHT_PHASE` reads 13 after a landing, 2 with the engines started, 3 at takeoff thrust.

Other things a flight showed:

- **After power-up** the OIS shows "OIS NOT AVAIL" (`#BootOIS`) for several minutes and boots by itself.
- **AP DISCONNECT PROTECTION** (OIS OPTIONS > SIMULATION): AP 1 dropped and came back by itself in about 3.5 s at FL300, with the master warning and AP OFF.
- **Pushback** (`Push back straight`, OIS GROUND): 2.5 kt, and it ends itself after about a minute (`PUSHBACK STATE` 0, then 1, then 3).
- **BTV** took the autoland at OMDB 12L to the exit it was given: at touchdown the FMA autothrust reads `BTV, green` and `DECEL, green`, the aircraft came to the exit at about 14 kt,
  and BTV ended with `AUTO BRK OFF`, amber, and the master caution, the brakes released and the aircraft rolling on: brake or steer before that.

### Pedestal levers (`A350Levers`, live 2026-10-27)

The map lists the levers as "none": each bypasses its input event, so they are written in C# the way the cockpit's own
lever code writes them, with the A380's rows and words (the A320 and Fenix agree where they overlap):

| Row | Positions | Written with | Read from |
|---|---|---|---|
| Flaps | Up, 1, 2, 3, Full | `n×4096 (>B:AIRLINER_Flaps_Set)` (its set code fires `'INI.FLAPS_SET'`); the aircraft picks 1+F itself | `INI_FLAPS_HANDLE_INDEX` 0 to 4 |
| All thrust levers, Thrust lever 1, 2 | Reverse (-20), Reverse idle (-6), Idle (0), Climb (25), Flex/MCT (35), TOGA (45) | `tla (>L:INI_TLAn_REQUEST)` | `INI_AUTOTHRUST_TLA:n`; All reads lever 1 |
| Speed brake | Retracted, Quarter, Half, Three quarters, Full | `'INI.SPOILERS_ARM_OFF' (>F:KeyEvent) x 'INI.SPOILERS_SET' (>F:KeyEvent)` (x 0 to 16384) | `INI_SPOILERS_HANDLE_POSITION` 0 to 1 |
| Ground spoilers | Disarmed, Armed | arm: `0 'INI.SPOILERS_SET'` then `'INI.SPOILERS_ARM_ON'`; disarm: `'INI.SPOILERS_ARM_OFF'` | `INI_SPOILERS_ARMED` |
| Parking brake | Off, On | its input event (the toggle `K:PARKING_BRAKES`), only when the state differs | stock `BRAKE PARKING POSITION` |
| Rudder trim left / right (nudge) | press | the switch at 2 (left) or 0 (right) for 300 ms, then 1: about 0.43 degrees | `RUDDER_TRIM_ACTUAL_ANGLE`, negative left |
| Rudder trim reset | press | its input event (`'INI.RUDDER_TRIM_RESET'`) | the trim back to 0 |

Reverse idle is -6: the commanded N1 (`INI_ENGINE1_TLA_N1`) rises 0.95 per degree from idle (21.3) to -6 and 1.29 per degree
from there to -20 (45). The rudder trim switch trims about 1.6 degrees a second while held, so it is two nudges, as on the
A380 and the Fenix, never a combo left trimming. The stock `SPOILERS HANDLE POSITION` does not follow the A350's handle (51 %
against 0.366), so there is no fine speed brake slider; quarters stand in for it. The stock fuel tanks and rudder trim do not
follow the aircraft either: refuel through the OIS (LOADSHEET, FUEL LOAD, SET FUEL, Instant Refuel).

Pitch trim is two nudges too (nose up, nose down), each holding both pitch trim switches for 1 s (0 nose up, 2 nose down,
1 off): the THS trims about 0.19 degrees a second, so a nudge is about 0.2 degrees. Either switch alone trims as well; the
A350 sets its takeoff trim itself (`FMGS_TO_TRIM_DEG`). Status lines beside them (`A350StatusLines`, shown, never spoken):
"Rudder trim: 1.2 degrees left" (or Neutral), "Pitch trim: 1.3 degrees up" (the stock `ELEVATOR TRIM POSITION`, which
follows the A350's `ELEV_TRIM_RATIO`), "Speed brake handle: 37 percent". The levers speak as the A380's do (`A350LeverSpeech`): "Thrust lever 1 Climb", "All thrust levers
Climb" once both sit there, nothing mid-travel; "Spoilers 40 percent", "Spoilers full", "Spoilers retracted" by tenths; each
under its own Ctrl+M row, after a silent baseline seeded from the cache after a load. Flaps, ground spoilers and the parking
brake are spoken by the generic path ("Flaps: 2").

### Typed values (`A350TypedEntry`)

A knob whose value the cockpit shows is one typed field in place of its increase and decrease rows, as the released aircraft type theirs: the FBW A320's FCU panel fields (Speed, Heading, Altitude, VS/FPA, validated and worded by `FcuValueEntry`, confirmed "FCU speed 250, selected") and the FBW A380's QNH ("QNH (in Capt unit)", the side's unit, "Altimeter set …") and pressurization fields. The value is landed by the aircraft's own click: the variable the click steps from is written one step short, then the encoder is clicked once toward it, so the aircraft's handler sets it with every side effect a turn has; a read-back after the click corrects it directly when the click landed elsewhere, and the value the cockpit then shows is said.

- Live 2026-10-26: the FCU dials are the FCU's state (`INI_HEADING_DIAL` 100 then a click read 101, and `AUTOPILOT HEADING LOCK DIR` 101; the altitude, speed, track and FPA dials alike). L:var names are case-insensitive (`INI_AIRSPEED_DIAL` and the WASM's `INI_Airspeed_Dial` are one variable).
- The aircraft's limits (WASM 1.2.7): `clampSpeed` 100-399 kt, `clampMach` 0.10-0.99, `ClampAltitude` 100-49000 ft, the V/S handlers ±6000 ft/min and ±9.9°.
- Each knob click sets a `*_COMMAND` / `*_INC` L:var the WASM consumes once per frame, so several clicks in one frame are one click, and fast clicks accelerate (`getRotationSpeed`): a value is never landed by counting clicks.
- Checked in flight (10,000 ft, AP 1 and FD on, 2026-10-26). A turn while a window is managed or dashed is a preset the pull then uses, and the mode stays: the speed knob while managed sets `INI_Preset_Dial` (FCU::Draw shows it for 45 s after `FCU_SPD_TIMER`, and the WASM drops `INI_FCU_SPD_DASHED` exactly then), the heading knob in NAV sets the dial with NAV kept, the V/S knob while dashed shows a preview (`FCU_VVI_TIMER`, about 45 s) with the pitch mode kept; each pull selected the preset. So a typed value into a managed or dashed window is confirmed "…, preset", and the status lines read the preset ("260 knots, preset", "Heading 310, preset"). Modes as the A350 numbers them: `INI_ROLL_MODE` NAV 1, HDG 2, TRK 11 (10 on the ground); `INI_PITCH_MODE` V/S 8, FPA 11, managed ALT 12. The A350's AP is `INI_ap1_on`; the stock AUTOPILOT MASTER does not follow it.
- The baro is the sim's own `value side r (>K:2:KOHLSMAN_SET)`, the event the A350's own `Baro_Inc_handler` fires; the click then runs `LinkBaros`, which copies the side to the other side and the ISIS when the OIS "linked instruments" option (`INI_LINKED_INSTRUMENTS`) is on. The cockpit floors hectopascals (the knob's tooltip, `flr '%dhPa'`): 1015.81 reads 1015, and so do MSFSBA's lines.
- On STD the knob sets a preset QNH, in flight only (on the ground it shows none). The WASM keeps it in its own memory (`INI_BARO_PRESET_CPT`/`_FO` are its output, whole hectopascals or hundredths of an inch, shown while `…_SHOW`): the first click shows it, each click while it shows is a step, and clicks one MCP round trip apart let it lapse. The pull sets the QNH from it (29.85 stepped to 29.89, the pull set 29.89). A typed QNH on STD is therefore stepped to by clicks 300 ms apart, read between them (`A350TypedStepper`), and confirmed "Captain altimeter preset 1015 hectopascals"; the status line reads "STD, preset 1015 hectopascals". Where no preset shows, it is said.
- The cabin targets drive the A350's own cabin model, not the stock pressurization variables (frozen): in MAN, a typed 3,000 ft target moved the cabin from 1,250 ft at 450 ft/min (CAB PRESS page, read with the display reader). Switching to MAN seeds the target from the cabin.
- The 100/1000 ft altitude increment is a value the WASM keeps to itself: a typed altitude with the 1000 ft increment lands on the 1000 ft grid and the read-back writes the typed value.

Learned on the way:

- SITUATIONS and OPTIONS show only on the OIS of the side chosen as PREFERRED SEAT SIDE (OIS
  SETTINGS); the first officer's menu lacks them while that is CPT. The failures are the
  Situation Manager's FAILURES tab; a press toggles one at once.
- GROUND refuses door toggles with "Unable to toggle when moving or engines running" while an
  engine master is on, even with the engines stopped (a flight test left both on).
- COMPUTE results arrive a few seconds after the press and are said once they hold for a read
  ("Results: V1: 141 kt, VR: 143 kt, ..."; `A.computeAnswer`, waiting up to 30 s); a COMPUTE that ends in an
  error line says only the error, which is its own alert.
- **Credentials** [A350-12]. With OPTIONS > STREAMER MODE on, a field labelled ID, KEY, LOGON, PASSWORD or TOKEN on
  that page, and any password input, reads "hidden" with its length ("SIMBRIEF USER ID, hidden, 7 characters";
  `A.isSecret`, `A.hiddenName`). Its value still reaches the EFB shell, masked in a password box (an empty box would
  make list mode's Enter wipe the field), and is never spoken or logged; a value set into it is confirmed as "Set,
  hidden, 7 characters" (`FbwEfbForm.FieldSetSpoken`). Typing into it still works key by key. With STREAMER MODE off,
  those fields read as the OIS shows them. No fixture keeps a credential (`secrets.test.js`).
- **An unchanged page is not shipped again**, as the MD-11 reader's: a MutationObserver (disconnected while the agent
  itself reads) and capture-phase change and input listeners mark the page changed; a full read still runs every tenth
  poll and on every poll while a COMPUTE answer is pending or held.
- **Colour words.** A painted button says its colour only when it has one: grey when its channels are within 30 of each
  other, red only when red leads; otherwise no word.
- The OIS shows "LDA 1019 FT" for VCBI 22 against a 10,961 ft runway: its own value, read as shown.
- The OIS keeps the last opened company message on screen when another box is chosen; an AOC
  request box (LOADSHEET, ADC DELAY, DIVERSION) shows no form without a SimBrief plan.

## The FAP and the printer (live 2026-10-30)

Input Ctrl+Shift+F is the A350's window list (`A350WindowsForm`, the Fenix's key): the windows with no hotkey of their own.

**The FAP** (`coherent-a350-fap-agent.js`, `CoherentPmdgEfbClient.ForA350Fap`, the shared `FbwEfbForm`) was read from its own script, `ini-fap-a350.js`, and every control pressed live through the agent. Two views, "VCockpitNN - iniFAPA350", show the same panel from the same L:vars, so the first is held. What the script does, as the agent reads it:

- **The screen off** is an image over everything (`#iniFAP > img`, `L:INI_FAP_SCREENSAVER`), and the FAP sets it itself 1.1 s after load: every FAP starts with its screen off. The agent then shows only *Wake the screen* (a press on the image), as a sighted pilot sees nothing else.
- **A tile that only looks like a button.** Caution, the Temp page's Zones, its zone tiles and its requested figure have the `is-button` class and no `onclick`: a press does nothing, so they read as text. `A.handlersKnown` needs a tab's `onclick` to tell, so a fixture (a saved page has no handlers) reads them all as buttons. Cabin Status's five tiles press through their pictures (`img.onclick`), and Smoke Detect's handler is only a comment (`A.inert`: *has no page*). `FAPSmoke` exists and is never shown.
- **State.** A door's state is its indicator's colour, from the page's own legend; Cabin Ready is read from `L:INI_FAP_CABIN_READY`, as the paint follows only a press on the same view. Toasts (`notie`) are alerts.
- **A level says Medium Dim after a page change.** On entering Lights the script compares the potentiometers (`INI_POTENTIOMETER_60` cabin, 44 avionics, 43 cargo) with 20 and 100, but writes them 0 to 1: anything but 0 reads Medium Dim, whatever is set. The agent reads what the panel shows.
- **Temp.** The flight deck holds the temperature while `L:INI_TEMP_KNOB2` is 5 or more (the overhead Cabin temperature knob), and the page then shows only *Temperature controlled by flightdeck*.
- **Pictures.** The outlines are fixed drawings of the aircraft from above, nothing on them changes: one line per page says what each shows.

**The printer** (`A350Printout`, `A350PrinterWindow`): `A350_Printer.js` takes the module's `PRINTCALLBACK` over the comm bus and writes the text into `#paper`, wrapped at 78 columns, on both "VLivery0N - A350Printer" views. No sim variable marks a print: `INI_PRINTER_PAPER_OUT_PERCENT` stays at 50 until the paper is torn, `INI_PRINTING_SOUND` stays at 1, so `A350PrinterWatch` reads the paper every 5 s at a batch end (a printout's header holds its time, so a reprint differs) and says the new title on its Ctrl+M row. `AIRLINER_PRINTER_PAPER_PED` writes `INI_PRINTER_TRIGGER_PAPER_TRANSFER`, which the module takes at once (out percent 0, `INI_PAPER_SOUND` a moment, `INI_PRINTER_SIDE_PAPER_VIS` 1 to 4 picks where it lies), so its row is a press. The eight `PRINTER_PAPER_SIDE_n_CS` clickspots set that 0. `INI_PRINTER_STATUS_1` and `_2` only light two lamps and nothing writes them.

**`UIRectangleCheckbox`** (the PRINTER page's AUTO PRINT boxes): no text of its own; its fill is drawn when it is on the screen (RAD NAV keeps two never drawn), its cross is a cyan stroke inside it, and its name is the text nearest left on its row under the title above its column. `INI_PRINTER_AUTOPRINT_FPLAN_INIT`, `_TODATA` and `_WIND` follow the top three; the three report boxes under ACTIVE F-PLN REPORT took no press while their PRINT keys were grey.

## The ATC mailbox (live 2026-10-30)

`SD::DrawMailbox` draws at the top of the CTR's right half (`A350DrawLayout.CtrMailbox`, y under 270; no WD line was ever drawn above y 307), so its lines are never the WD's or said as E/WD lines. `A350Mailbox` reads it, `A350MailboxWindow` shows it (Input Ctrl+Shift+D, the DCDU's key), Alt+E adds its text.

- **NOT AVAIL.** `MAILBOX NOT AVAIL` (amber, at 229,135) is drawn while bus 81 has no power, or within 20 s of a timer (start-up): on batteries it stays. With the GPU connected and EXT on it goes.
- **Controls.** As on the ND, all are in every draw. A control is on the screen when its fill is drawn; its texts are those between its `TextStart` and the next control's; SEND is drawn over CLOSE, so a later control at the same spot hides the earlier. Text: PRINT, RECALL, CLOSE, WILCO, STANDBY, UNABLE, ACCEPT, REJECT, SEND, CANCEL. Pictures, by position: (864,9) and (865,125) the message arrows, drawn only with two or more; (1393,50) and (1393,94) the page arrows.
- **Press.** `A350MailboxInput`: the captain's KCCU MAILBOX key brings the cursor (`INI_CPT_CURSOR_SCREEN` 3), then the Coherent mouse route into the view holding the CTR gauge, at the draw's own coordinates.
- **Text.** The message is black on a cyan box (970,50 to 1386,190), said *on cyan*. MSG and its count stand left of the box, PGE and its count right of it. A header's time and station are green. `ACTIVE ATC: {}`, `ADS OFF`, `1 ADS-C CONNECTION`, `OPEN`, `SENDING` and `SENT` are the module's other strings.

Exercised without sending: a departure clearance request (ATC COM, REQUEST, CLEARANCE, DEPARTURE, GATE and D-ATIS CODE typed, XFR TO MAILBOX) shows TO VCBI with PRINT, SEND, CANCEL; the page arrows scroll it; PRINT prints `MAILBOX MESSAGE RECEIVED`; a second request gives MSG 1/2 and the message arrows; CANCEL on 2/2 emptied the list. **Not exercised:** SEND, an uplink and its replies (WILCO, STANDBY, UNABLE, ACCEPT, REJECT, CLOSE, RECALL), `INI_ATC_MSG_LIGHT` on an uplink: each goes out through `INI_CPDLC_SOURCE`'s network, so they wait for the owner's go-ahead.

**ATC COM** (`FMS_ATC_MENU_PAGE`, KCCU ATC, the window's Alt+A; walked live 2026-10-30, nothing sent). Tabs CONNECT, REQUEST, REPORT & MODIFY, MSG RECORD, D-ATIS and EMER, the last black on amber above the title bar, a key like the others (`A350MfdPage.InTitleBar`: the title bar's band starts at y 108). What enables a REQUEST key is its `function<bool()>` lambda in the constructor: VERTICAL, LATERAL, ADD TEXT and the rest, and CLEARANCE's OCEANIC, are disabled while `AircraftVariables::GetInt(3)` is 1 (true on the ground); GENERIC's always returns true, so it never enables; DEPARTURE's has no such lambda. DEPARTURE's XFR TO MAILBOX (`TransferToMailbox`, `AllFieldsFilled`, `MailboxBuilder::BuildDepartureClearance`) needs GATE and D-ATIS CODE and gives the mailbox its request; `BuildOceanicClearance` and the altitude, speed, offset and direct requests are its neighbours. EMER's ten keys (MAYDAY, PANPAN, CANCEL EMER, CLIMBING TO, DESCENDING TO, DIVERTING/VIA, OFFSETTING, REQUEST VOICE CONTACT, ENDURANCE & PERSONS, ADD FREETEXT) are lambdas 343 to 352 with empty bodies: a press only moves the cursor on 1.2.7, so MSFSBA reads them and a press changes nothing, as for a sighted pilot. D-ATIS's three rows fill from the F-PLN (origin, destination, alternate).

## Variants
